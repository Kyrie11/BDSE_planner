Bug fixed
---------
The first speed package incorrectly applied pathlib.Path.stem to dotted nuPlan log identities and also assumed cached log_name must equal one raw DB filename stem. Example: Path('2021.08.23.18.41.38_veh-28').stem becomes '2021.08.23.18.41'. Raw nuPlan DB filenames may additionally carry numeric crop suffixes. The hotfix preserves dotted log identities, normalizes the known crop suffix, optionally disambiguates multi-chunk log families via read-only SQLite token lookup, and otherwise widens only the raw DB search set while retaining the exact frozen scenario-token filter.

New DB/provenance contracts tested
---------------------------------
1. Dotted nuPlan log identities are preserved exactly; only a literal .db suffix is stripped.
2. DB crop stems such as <log>_00001_00099.db normalize to the stable cached log identity.
3. Multi-chunk stable-log families can be resolved by exact read-only SQLite lidar-pc/scenario-tag token membership when supported.
4. If a unique raw DB cannot be proven, the runner retains a safe DB candidate set rather than dropping/stopping a frozen token; exact scenario_filter.scenario_tokens remains the final scientific population filter.
5. Batch completion certificates bind the actual per-batch raw-DB candidate-list SHA256, so a changed DB search set invalidates resume.
6. Probe-only diagnostics, heartbeat, unlocked shared-model inference and deterministic batch resume remain unchanged from the speed patch.
