New engineering contracts tested
--------------------------------
1. PIOR probe-only diagnostic mode writes no row on ordinary ticks and exactly one minimal event payload when the one-shot probe fires; the full diagnostics tree is not serialized in this mode.
2. Historical/default closed-loop diagnostic semantics remain unchanged unless BDSE_CLOSED_LOOP_DIAG_MODE is explicitly set by the PIOR runner.
3. Resume certificates require exact token/config/checkpoint/challenge identities, the exact per-batch raw-DB path-list SHA256, successful/failed counts, exact probe count, normalized metric SHA256 and probe-event SHA256. Mutating a metric file or changing the DB subset invalidates resume.
4. Optimized launcher exposes deterministic batch resume, heartbeat telemetry and a conservative switch to restore serialized GPU inference.
5. Exact raw DB restriction is all-or-nothing; every frozen token must map to a direct raw *.db file before collection.

Performance changes (no scientific-semantic changes)
-----------------------------------------------------
- exact DB subset rather than four complete TRAIN split directories;
- BDSE_SERIALIZE_GPU_INFERENCE defaults to 0 for shared read-only per-arm CUDA inference (can be restored with PIOR_SERIALIZE_GPU_INFERENCE=1);
- PIOR event-only diagnostics rather than full diagnostics every planner tick;
- 30 s parent heartbeat with phase/probe/GPU telemetry;
- per-batch closed-loop timing profile;
- deterministic batch completion certificates and resume;
- fully complete legacy 502-scene arm may be reused only after strict validation; partial legacy arm is never reused.

Not changed for speed
---------------------
No replan interval change; no horizon shortening; no scenario subsampling; no candidate/top-K/RSMR change; no approximate selector; no treatment/control action change; no metric removal; no probe-time change.
