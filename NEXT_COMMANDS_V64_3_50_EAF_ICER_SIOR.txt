V64.3.50 LIVE-SELECTION ELIGIBILITY / COHORT REPAIR
----------------------------------------------------
The V49 502-scene set is now explicitly treated as an OFFLINE DISCOVERY COHORT,
not as 502 guaranteed native closed-loop treatment events.

During paired replay, each token is classified as:
  eligible_intervened
    both arms reach the same live RSMR proposal event; CONTROL vetoes and
    TREATMENT executes that same live winner exactly once. This row receives a
    paired selected-outcome label and may enter SIOR fit/calibration/test.

  no_live_proposal
    neither arm ever emits a live RSMR proposal. This is a label-free
    offline-to-live selection-transport observation, NOT a negative SIOR label.
    The whole C/T deployed-candidate fingerprint trace and official metrics must
    remain equivalent. The row stays in the 502-scene audit but is excluded from
    outcome fitting.

If only one arm emits a proposal, or the no-treatment traces/fingerprints differ,
that remains an ENGINEERING STOP.

Because this changes the paired CSV schema/estimand bookkeeping, do not resume a
paired_train directory created by an earlier V50 repair. The current collector
checks `collection_protocol_version` and will refuse to mix old rows. Before the
first run of this package, remove ONLY V50 paired collection state:

  rm -rf outputs_v64_3_50_eaf_icer_sior_screen_2gpu_v1/paired_train

Then rerun the normal launcher. Do not delete or rerun V49 outputs.

V50 introduces no post-hoc live-eligibility-rate threshold. Instead the live
selected-event population must satisfy the already-frozen V48/V49 estimator
support requirements (>=32 benefit/nonbenefit in every nested fit split, >=16
benefits in every calibration fold, both classes in every test fold). If not,
V50 writes the cohort-transport audit and SCIENTIFIC STOPs before SIOR fitting or
fresh evaluation; do not relabel no-proposal scenes or lower these minima.
